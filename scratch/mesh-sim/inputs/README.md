@page inputs inputs

@brief Scenario definitions (`run.ini` + JSON files) that drive mesh-sim runs, plus RL experiment and sweep specs.

Each scenario is a directory holding the files that drive one simulation run.
Scenarios only describe inputs; run products go to `outputs/`.

## Module Layout

| Path | Role | Git |
|---|---|---|
| `baselines/` | Numbered synthetic scenarios 01-16 for deterministic validation, plus fixtures `p0-smoke`, `p0-jammer-smoke`, `rl-test`, `centralized-multi-smoke`, `building-bypass-smoke`. See @subpage inputs_baselines | Tracked |
| `calfex/` | Field-derived CalFEX sub-6 scenarios (`<HHMM-HHMM>/` with `run.ini`, `nodes.json`, `jammers.json`), generated by `scripts.validation.build_config_files` | Ignored (`inputs/.gitignore`); regenerate from field data |
| `sweeps/` | Parameter-sweep specs for `scripts.sweep.cli`; only `example.ini` is tracked | Only `example.ini` |
| `experiments/` | RL experiment matrix (`bypass-smoke-matrix.json`, run by `scripts.rl.experiment`) and tuning study (`bypass-smoke-study.json`, run by `scripts.rl.ops.tune`) | Tracked |
| `custom/sherpa/` | Local Spring Lake ARPO mmWave scenarios; not present in a clean checkout, ask the project team or data owner | Ignored, read-only |

Sherpa and CalFEX are distinct field workflows: the Sherpa inputs describe ARPO
mmWave trials, the CalFEX inputs describe sub-6 field scenarios.

## Scenario Files

| File | Required | Role |
|---|---|---|
| `run.ini` | yes | Simulation parameters. Keys and defaults: [run.ini reference](../src/config/run-ini-reference.md) |
| `nodes.json` | yes (path from `nodes_file`) | Node positions and mobility; IDs unique, all `role: "peer"` |
| `buildings.json` | no (`buildings_file`) | Building geometry |
| `jammers.json` | no (`jammers_file`) | Jammers; only active when the band is `sub-6` |

File paths inside `run.ini` are relative to the `run.ini` file.

## Band Selection

The band resolves as `--band` > `[channel] band` in `run.ini` > default `mmwave`.
The `calfex/` scenarios do not set `band`, so pass `--band sub-6` for their
jammers to take effect.

## Run

From the ns3-mmwave repo root, with an already-built binary:

```bash
./build/scratch/mesh-sim/ns3*-sim-* \
  --run-config=scratch/mesh-sim/inputs/baselines/01-static-los-baseline/run.ini
```

Outputs go to a timestamped directory under `scratch/mesh-sim/outputs/`.
From `scratch/mesh-sim/`, sweeps and experiments run as:

```bash
python -m scripts.sweep.cli --config inputs/sweeps/example.ini --dry-run
python -m scripts.rl.experiment --help
python -m scripts.rl.ops.tune --help
```

## Related Directories

- `data/`: local raw and derived field telemetry, read-only input to the
  validation generators; git-ignored.
- `outputs/`: disposable and git-ignored; never commit raw run products.
- `tests/fixtures/regression/p0/`: regression reference snapshots, external and
  untracked except `manifest.json`; never recapture them from changed code.

## Design philosophy

The numbered baselines are ordered by complexity.  Each one changes **exactly one
knob** from scenario 01, so you can always diff back to understand what
changed.  See [Baseline Scenarios](@ref inputs_baselines) for the full table
and a guide to interpreting the output graphs.
